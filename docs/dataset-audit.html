Nota Pembelian Audit

A forensic read of the Roboflow corpus behind the receipt-scanning model — what it actually contains, one defect that invalidates every accuracy number reported so far, and one property that turns out to be worth building the architecture around.

The corpus is photographs of handwritten Indonesian purchase notes on the standard pre-printed nota booklet — the ubiquitous BANYAKNYA / NAMA BARANG / HARGA / JUMLAH carbon-copy form. Ballpoint on tinted paper, shot flat and well lit. No thermal receipts appear in the sample examined.

Findings

Blocker

The train/val/test split leaks almost completely

Version 9 contains 1,295 images but only 440 distinct receipts: Roboflow generated three brightness-darkened copies of each source (415 notes × 3, 25 × 2). The current preparation code splits on COCO image_id, and the three copies of one receipt carry three different image_ids — so they scatter across all three partitions.

Re-running that split reproduces the reported 1036 / 129 / 130 partition exactly, which confirms the replication. Of the 118 distinct receipts landing in validation, 115 also appear in training. The model is being evaluated on receipts it memorised, differing only in brightness.

The genuinely unseen evaluation set is three receipts in validation and three in test. Every accuracy figure produced from this split is meaningless, and would not survive a judge asking how the data was partitioned.

FixGroup by source filename — parse nota203 out of nota203_jpg.rf.<hash>.jpg and split on that identifier, never on image_id. Better still, hold out by writer: handwriting style, not receipt identity, is the real generalisation boundary.
Major

The corpus is far smaller than the annotation count suggests

The headline 18,585 annotations reduce to roughly 6,300 distinct handwritten tokens once augmentation is removed — a median of 14 per receipt, ranging from 5 to 38. Reconstructing complete rows yields 1,011 usable line items across 439 receipts, about 2.3 per note. Most rows on most forms are blank.

Augmentation is brightness reduction only, up to 20%, with auto-orient as the sole preprocessing. There is no rotation, no perspective warp, no blur, no occlusion — none of the degradation a phone photograph in a warung actually introduces. Every image is 1536×2048; median annotation box is 176×76 px.

ConsequenceData volume, not model architecture, is the binding constraint. Plan the synthetic pipeline as the primary workstream rather than a supporting one.
Major

Labels are word-level over a closed vocabulary with a long tail

The 739 COCO categories are not object classes — each is the literal text inside one box. They divide into 328 numeric strings (quantities and prices: 1, 8, 1500, 17000) and 411 Indonesian words (indomie, teh, gula, kentang). A product name spans several boxes: kentang goreng ori is three separate annotations, not one field.

The distribution is severely long-tailed — 274 of the 738 used classes appear three times or fewer, while 1 alone appears 921 times.

ImplicationTrain a character-level recogniser, never a 739-way classifier. Treated as classes, three-quarters of the vocabulary has too few examples to learn and the model can never emit a product name it has not seen. Treated as character sequences, the same data teaches glyphs that compose into unseen words — so build the character dictionary from all 739 category names, not from the training split alone.
Context

The form is a fixed template, which removes most of the layout problem

Every receipt uses the same printed booklet with the same four ruled columns in the same positions. Nothing in the annotations marks a box as a price rather than a quantity — but nothing needs to. Field type is recoverable from horizontal position alone, and the column boundaries sit near 0.21, 0.62 and 0.77 of image width.

That geometric assignment is what made the arithmetic check below possible, and it collapses key-information extraction from a learned problem into a solved one for this document class. It also fixes the limit: the assumption holds for this booklet and fails for any other supplier's layout.

ImplicationDo not spend model capacity on layout understanding for the MVP. Spend it on recognition, and treat generalisation beyond this template as declared future work.

The property worth building on

Across 439 de-duplicated receipts, 992 of 1,011 reconstructed line items satisfy quantity × harga = jumlah — 98.1%.

The document verifies itself. Every line carries a redundant third value, and the column total carries another. Because handwritten digit recognition is where errors will concentrate — and a wrong digit silently corrupts inventory in a way a shop owner cannot detect — this redundancy is not a nice-to-have. It is the mechanism by which the system can catch its own mistakes, and, using per-character confidence to search digit substitutions that restore the identity, sometimes repair them.

The 19 violations deserve honesty rather than dismissal. Several are off by exactly a factor of ten, which points at digit grouping in this audit's geometric reconstruction rather than genuine writer error; others look like real mistakes by whoever wrote the note. Both categories matter. A reconciliation layer must therefore flag irreconcilable lines for user confirmation rather than silently rewriting them — the receipt is sometimes wrong, and the system must not pretend otherwise.

What this changes

  • Re-derive the recognition dataset before training anything. Split on source receipt; the current crops cannot support any claim about accuracy.
  • Synthetic data is the critical path, not the model. Two or three handwriting styles across 440 notes will not generalise to an arbitrary supplier's handwriting. Because the form template is a known, renderable object, synthetic handwriting can be composited into real template cells — a far more tractable problem than synthesising receipts from nothing.
  • Character-level recognition, geometric field assignment. The vocabulary is too long-tailed to classify and the layout is too fixed to need learning.
  • Report writer-held-out accuracy. With a fixed template and a closed vocabulary, a random split flatters the model. Handwriting style is the axis that will break in deployment, so it is the axis to evaluate on.
  • Expect the deployment gap. These photographs are flat, sharp and evenly lit. Real submissions will be angled, shadowed and creased, and none of that appears in the augmentation.

Reproduction

Every figure above is recomputed from the COCO export by grouping images on the source identifier embedded in the Roboflow filename. The split replication reproduces the original 1036 / 129 / 130 partition exactly, which is what licenses treating the contamination rates as measured rather than estimated.

source_id  := regex ^(.*?)_jpg\.rf\.        # nota203_jpg.rf.93fc05...jpg -> nota203
split      := train_test_split(image_ids, test_size=0.20, random_state=42)
              then  train_test_split(temp, test_size=0.50, random_state=42)
columns    := qty [0.02,0.21)  name [0.21,0.62)  harga [0.62,0.77)  jumlah [0.77,0.97)
              as fractions of image width (1536 px, constant across the corpus)
rows       := cluster annotation centres into bands of 0.025 x image height
Audit performed on the full COCO export (331 MB, 1,295 images, 18,585 annotations). Figures are measured, not sampled, except the printed-versus-handwritten determination, which rests on visual inspection of twelve receipts.
